# Discipleship-only removal and cleanup

## Ownership audit

The removed Sermons experience had its own catalog, navigation, coaching, reader,
quiz/flashcard screens, audio playback/downloads, search, reminders, and progress.
Its runtime was `js/sermons.js`, `js/sermons-ui.js`, and the older
`js/sermon-audio.js`, with wiring in `js/app.js`, `index.html`, the native bridge,
the build script, and the service worker. The catalog was empty; the separate
sample deck and MP3 were placeholders. Sermon-only validation, tests, prompts,
and integration handovers have been removed. Generated `dist` is rebuilt and
explicitly prunes the retired paths, even when building over an older output.

Local ownership is explicit:

- `sermons` in a study profile owns sermon progress, coaching completion, quizzes,
  downloads, reminders, and playback position.
- `settings.showDraftSermons` and `settings.experience` belong to the retired
  experience selector. All other settings remain.
- `cci-sermon-downloads-v1` and `cci-sermon-audio-v1` are exclusive browser caches.
- `Directory.Data/sermon-audio/` is the exclusive native download directory; its
  filenames were generated by the retired audio store.

At launch, an idempotent migration edits only these fields in the `current` and
`account:*` records of IndexedDB `cci-study-data/state`, and localStorage
`flashdecks.v1` / `flashdecks.v1.account.*`. It includes inactive account profiles.
Malformed JSON and unknown records are left untouched. Write failures preserve
records and trigger a retry on the next launch. Save and backup-import paths
prevent the old fields returning. Old backups on disk are not rewritten.
Both browser caches and the native directory are cleaned on launch; service
worker activation also removes both named caches and refreshes the shell cache.
Cleanup failures are logged and retried without blocking study.

## Shared data and features retained

Discipleship decks/progress, custom decks, quiz scores, daily counts, streaks,
onboarding, devotionals, paused study sessions, backup preferences, device IDs,
authentication tokens, and sync baselines remain. A custom deck is not deleted
because its title or ID contains “sermon”: its ownership cannot be inferred.
Bible references, ESV previews, private lesson videos, captions/transcripts,
account flows, guest import, and progress synchronization remain.

`js/progress-sync.js` extracts only canonical Discipleship deck progress, daily
counts, streaks, and device counters. The shared `public.user_progress` table and
its authenticated RPCs are retained. No sermon-only API, Cloudflare Function,
Supabase table, or dependency was found. Capacitor Filesystem is still needed for
native backup sharing and the scoped retired-download migration; the other
Capacitor and Supabase dependencies remain in use.

## External cleanup: not executed

No production data, R2 object, Supabase row, or deployed site was changed for this
removal. No production migration is needed for the cloud schema inspected here.
The `LESSON_VIDEOS` binding and `cci-lesson-videos` bucket contain Discipleship
lessons and must be preserved. Do not delete shared cloud records or infer sermon
ownership from filenames, titles, or a broad text match.

If a separately managed hosted sermon catalog or audio store exists outside this
repository, its cleanup requires authorization after a read-only inventory:

1. Identify the exact catalog records and object keys with evidence of exclusive
   sermon ownership; exclude all lesson-video and transcript keys.
2. Export the candidate records, object metadata, and recoverable copies; prepare
   an exact allowlist and rollback procedure.
3. Present that allowlist for authorization. Delete only approved objects/records,
   using version/ETag guards where available. No bucket-wide or table-wide deletion.
4. Verify all retained lesson assets and account progress against the inventory.

Local browser/native cleanup takes effect only when this code is installed and
run. Existing production clients and their data are unchanged until an authorized
deployment. External exports and backups remain user-owned.

## Changed files and verification

Runtime changes: `js/app.js`, `js/storage.js`, `js/native-bridge.mjs` and its
bundle, `index.html`, `style.css`, and `service-worker.js`. Build changes:
`scripts/build.js`, `package.json`, and regenerated `dist/`. Shared regression
updates: `tests/storage.test.js`, `tests/content-lint.test.js`,
`tests/account-ui.test.js`, and `tests/pwa.test.js`. Documentation changes:
`README.md`, `design-qa.md`, and this audit. Retired modules, catalog/sample
assets, validator, dedicated tests, prompts, and Sermons-only handover templates
were deleted. Concurrent account changes and their tests, lockfile edits, and
an unrelated QA handoff were left intact.

Validation: `npm run build`, `npm test` (all 18 test files), and
`git diff --check` pass. Storage regression cases cover inactive account and
guest records, malformed JSON, unknown/custom records, idempotence, failed
writes, and preventing legacy fields from returning. PWA tests cover retired
cache removal and preservation of private lesson API/transcript handling.

A local Cloudflare Pages preview was checked in the browser: Discipleship-only
navigation and onboarding, account form controls, quiz scoring and Bible
references, quiz progress/resume after reload, flashcard reveal and advancement,
and lesson video/part selection with the guest sign-in gate. Authenticated
production sign-in/sign-up and private video streaming were not exercised;
existing account/video regression tests pass. Native-device cleanup was not
run on a physical device. No commit or deployment was made.
